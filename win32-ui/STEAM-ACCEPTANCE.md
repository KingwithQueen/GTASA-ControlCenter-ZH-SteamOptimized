# 经典 Steam 版 GTA SA 实机验收

这是圣安地列斯控制中心的 Win32 便携测试包。开发环境的离线界面测试和后端夹具用于检查交互及接口。本次实机验收状态为**待验证**，需要用下述匹配版本和可读取的单人存档实际观察结果。

## 准备和连接

1. 完整解压 ZIP 到独立目录。将 `GTASAControlCenterUI.exe` 和 `GTASASteam.dll` 保持在同一目录，直接启动 EXE。测试包不需要安装程序、OCX 注册或把文件复制进游戏目录。
2. 核对 Steam 实际启动的游戏 EXE。当前后端验证的是经典 Steam 版的**一个确定版本**，其 SHA-256 为 `15e3cfedba9a841df67d8194e7249afb493b0e10d6138fb8ebab2c136e543efb`。

   ```powershell
   Get-FileHash -LiteralPath 'D:\实际游戏目录\gta-sa.exe' -Algorithm SHA256
   ```

3. 启动游戏并载入供测试的单人存档，记录测试前的进度。打开控制中心，待状态栏确认已连接经典 Steam 版。若显示版本或运行布局不匹配，保留状态栏信息并记录为未通过连接前置检查。若显示当前状态不允许操作，确认存档已载入并按相应操作的提示切回游戏或暂停。
4. 在控制中心依次点击六个主标签页，再用 `Ctrl+Tab` 和 `Ctrl+Shift+Tab` 来回切换。确认界面正确显示，选中的设置保留，连续切页时留意是否出现明显停顿。

如需校验下载，在 ZIP 和 `SHA256SUMS.txt` 所在目录执行以下命令，把输出与清单的 ZIP 条目对照。

```powershell
Get-FileHash -LiteralPath '.\GTASAControlCenter-SteamPreview-Win32.zip' -Algorithm SHA256
```

## 六个标签页

| 标签页 | 实机操作 | 应观察到 |
| --- | --- | --- |
| 载具与游戏 | 在游戏中驾驶一辆普通汽车。切到控制中心的载具页，打开主色和副色色表，分别选两个容易区分的颜色并确认。将当前颜色与游戏画面对照，再测试一个天气选项。 | 色表和选中编号分别保留。后端报告完成后，游戏中的相应颜色和天气改变。车型本身只有一个可见色区时，可换一辆双色汽车。 |
| 玩家状态 | 查看生命和护甲，选择一项做小幅修改并核对游戏状态。分别切换“主角防火（伤害）”“主角防火（秘籍）”和“锁定防火秘籍”，记录三个控件的状态，再恢复原样。可在武器页对一个已持有武器测试弹药输入、应用和读回。 | 可读取当前角色状态。支持的写入会反映在游戏及界面中；两种防火与各自的锁定设置彼此独立。 |
| 车库 | **让主角在室外步行，关好要写入的车库门，在游戏中按 Esc 暂停，再切回控制中心。** 点击“读取游戏车库”，选一个已停有普通汽车的车位，修改颜色后点击“写入游戏车库”。恢复游戏并检查车库。若测试车库锁定，再按 Esc 暂停后操作，结束时取消锁定。 | 读取覆盖 17 座车库。写入报告修改的车库数，游戏中显示所选车位的新颜色。当前测试包以普通车辆为验收对象。 |
| 游戏秘籍 | 选择易于观察的天气类秘籍。先试“复制秘籍代码”，再点“向游戏输入秘籍”。看到排队提示后及时切回同一个已连接游戏窗口。 | 复制会得到选中的代码。发送完成后可在游戏中观察该秘籍的效果；未切回游戏时记录是否超时。 |
| 传送地点 | 点击“读取游戏位置”，记录当前 X、Y、Z 和朝向并保存为一个临时地点。让主角走开几米，然后选中临时地点并点击“传送到坐标”。另外用地图缩放、拖动、点选及“从地图读取 XY”核对坐标流转。 | 可读回当前位置并在地图上看到标记。传送后主角回到刚才记录的地点，再读一次位置可以核对结果。地图底图为区域示意图。 |
| 快捷键 | 新建一条测试绑定，选择容易观察的已支持控制中心命令，例如增加一小时，选择未被占用的按键并启用。分别在控制中心窗口和游戏窗口有焦点时按键；在游戏中短按一次，再试按住后松开。 | 只有已连接的游戏窗口有焦点时才执行。按住时同一次按键只触发一次。停用测试绑定后重试，确认游戏时间不受该绑定影响。 |

## 数值编辑和读取游戏数据

- 在「玩家状态」里关闭「永不通缉」，把「通缉等级」设为 2，观察游戏中的星数和追捕。再用「清除」将星数置零。在同页调整「总威望」和「总性感度」，用游戏统计页和刷新后的读数核对。游戏更新衣着、载具或其他相关状态时可能重新计算统计。
- 在「载具与游戏」的时间与天气区域编辑「义警累计击杀」。在游戏统计里核对义警任务的累计击杀数。当前一轮义警任务的目标进度由任务脚本另行维护。
- 在游戏中切换武器或改变弹药，然后在控制中心右上角点击「刷新游戏数据」或按 `F5`。刷新会读取玩家、载具、时间和天气，并更新地图上的玩家位置标记。车库仍通过「读取游戏车库」读取。
- 打开「玩家状态」的武器区，可以点「读取武器」。保持该区域可见时大约每秒自动读一次。核对当前武器名称、武器槽、弹匣和携带弹药。可先修改一行弹药但暂不点「应用」，再刷新并确认该行输入保留、当前武器读数仍更新。

后端显示“此操作缺少已验证的 Steam 实现”时，将该动作单独记为**未支持**。状态栏显示已提交时，等待后端结果并观察游戏状态，再给该项判定。测试后取消临时锁定和快捷键，从测试前的存档恢复游戏进度。

任务计时仍可通过「游戏开关」冻结。Steam 版现有校验覆盖冻结逻辑，直接读写倒计时需要核实目标版本中 HUD 绑定的脚本变量。红外设备是旧版目录中记录为不稳定的装备。车牌、生成器和首次启用部分增强项可能要求先按 Esc 暂停，再恢复游戏让请求执行。拖车传送和带拖车的历史载具操作请分别记录实机表现。

## 记录结果

建议记录游戏 EXE 的 SHA-256、控制中心 ZIP 的 SHA-256、Windows 版本，以及每一项的通过、失败、未支持或未测试。失败时保留发生步骤、游戏当时是否暂停、状态栏原文和可见现象。对车库问题补记车库名称、车位和载具型号。

## 从源码生成同类测试包

在装有 Visual Studio 2026 C++ 桌面开发组件的 Windows 上，从源码仓库根目录运行：

```powershell
powershell -NoProfile -File .\win32-ui\package-steam-preview.ps1
```

脚本用解决方案生成 Win32 Release，校验两个二进制均为 x86，再生成便携目录、ZIP 和独立的 `SHA256SUMS.txt`。输出默认位于仓库的 `.work\win32-ui` 下，也可以用 `-OutputDirectory` 指定一个新目录或空目录。旧版 Windows 以源码兼容为目标，应使用对应工具链重建并单独验证运行。
